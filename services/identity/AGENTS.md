# services/identity

## Overview

Owns proof of who you are: `tutor_id`, email, password hash, display name, timezone, language. It
mints the tokens every other service verifies, and serves the JWKS document used by a key rotation
step (never on a request path). It must never own bank details, an invoice profile, or anything about
teaching or money, and it holds copies of nothing.

## Stack

- **Module**: `github.com/nguyen-duc-loc/vermouth/services/identity`, Go 1.27
- **Database**: its own Postgres 18 instance, reached by `IDENTITY_DATABASE_URL` only
- **Key dependencies**: `pgx` v5 with `sqlc`, `golang-jwt/jwt/v5` (Ed25519), `golang.org/x/crypto/argon2`
- **Publishes**: `identity.events`, with `identity.tutor.registered` and `identity.tutor.profile.changed`

## Key files

| File | Owns |
|---|---|
| `cmd/identity/main.go` | Startup: config, logger, signer, verifier, pool, `EnsureTopics`, producer, relay, server |
| `internal/handler/tutor.go` | Registration: the business write and its outbox insert in one `pgx.Tx` |
| `internal/handler/convert.go` | Turning a stored row into the shape the boundary returns |
| `internal/http/routes.go` | Routing only |
| `internal/store/store.go` | The only path to this service's database |
| `internal/store/sqlcgen/` | Generated by `sqlc`. Never edit by hand |
| `internal/token/signer.go` | Minting with the private half of the Ed25519 key pair, which only this service holds |
| `db/queries/tutors.sql` | Hand written SQL, the input to `sqlc` |
| `db/migrations/` | `00001_vermouth_kit.sql` (copied from the shared module) plus this service's own |

## Commands

```bash
task generate:sql              # regenerate internal/store/sqlcgen from db/queries
task migrate:up                # every service, run before services start
task svc:start -- identity     # start just this one
task logs -- identity
```

## Conventions

- The password hash never leaves this service, and no event field carries it.
- A new query is hand written in `db/queries/`, then `task generate:sql`, then used through
  `internal/store`. Never assemble SQL at runtime.
- Registration is the working example of INV-3 and STK-4 in this repository. Copy its transaction
  shape when adding a write here or in another service.

## Gotchas

- This service holds the private signing key; everybody else holds only the public half. Never move
  a signing path into another service or a shared package.
- It publishes the event that seeds both `billing`'s empty invoice profile row and `notifications`'
  recipient row, so a change to `identity.tutor.registered` touches two consumers in other services.
